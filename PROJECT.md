# PROJECT.md — паспорт проекта

Файл читается агентом в начале каждой сессии. Это единственный источник
контекста: требования, договорённости, статус и следующий шаг.
В конце каждой сессии агент ОБНОВЛЯЕТ разделы 7 и 8 и включает обновление в коммит.

---

## 1. Суть проекта
3D-игра от первого лица с ASCII-графикой в жанре выживания.
Сеттинг: безлюдная снежная горно-лесная местность (снег, скалы, хвойные
деревья). Проект должен легко расширяться новыми
модулями без переписывания ядра.

## 2. Полные требования (из исходного запроса, не нарушать)

### 2.1 Рендер и визуал
- 3D-сцена от первого лица, отрисованная ASCII-символами.
- Цвет: строго 16-битная палитра (High Color, до 65536 оттенков, формат RGB565).
  Квантование палитры выполняется в рендерере, а не «откладывается на потом».
- Разрешение: не менее 1280×720 (720p), масштабирование под монитор.
- Полноэкранный режим (или borderless-окно) — реализованный, не заглушка.
- Система освещения: свет влияет на яркость и выбор ASCII-символа.

### 2.2 Игровые системы
- Инвентарь: хранение, выбор, использование предметов.
- Параметры персонажа: здоровье, голод, жажда, холод.
- Крафт: рецепты из доступных предметов (пример: ветка + камень = топор).
- Размещение: установка предметов и построек в 3D-пространстве.
- HUD: отображение статов и служебной информации (FPS и т.п.).

### 2.3 Управление и меню
- Клавиатура: WASD, прыжок, присед, спринт, взаимодействие, инвентарь, крафт, меню.
- Мышь: обзор, захват курсора в игре, освобождение в меню и подобных окнах.
- Переназначение клавиш через меню настроек (динамическое, с сохранением).
- Меню настроек графики: разрешение, полноэкранный режим, яркость,
  дальность прорисовки / плотность символов.
- Меню настроек звука: общая громкость, музыка, эффекты.
- Пауза при открытом меню.

### 2.4 Сохранения
- Сохранение прогресса: позиция, статы, инвентарь, постройки, состояние мира.
- Сохранение настроек и биндов отдельно (config).
- Формат файлов: JSON (System.Text.Json), папка Data.

### 2.5 Архитектура и дистрибуция
- Строгая модульность: Core / Rendering / World / Gameplay / Data / UI.
  Новые модули добавляются без правок ядра.
- Сборка в ОДИН .exe, запускаемый на обычном ПК без установленных средств
  программирования (.NET SDK, IDE и т.п.).
- Целевое железо: Ryzen 5 4600G, RTX 2060 Super, 16 GB RAM — стабильные 60 FPS в 720p и выше.

## 3. Стек и технические решения
- Язык: C# (.NET 8). Обёртка: Raylib-cs (OpenGL-рендер).
- Конфиги и сейвы: System.Text.Json.
- Сборка в один файл:
```
dotnet publish -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true
```
- Результат: единый exe в bin/Release/net8.0/win-x64/publish.

## 5. Технические правила для агента (известные грабли — не повторять)
- Имена клавиш в config.json хранить ТОЧНЫМИ именами энума Raylib-cs
  (KEY_W, KEY_SPACE, KEY_LEFT_CONTROL и т.д.); парсить через Enum.TryParse.
- InputManager использует распарсенный Dictionary<string, KeyboardKey>;
  не смешивать строковые бинды и энум-бинды в одном поле.
- MathF.Deg2Rad в .NET 8 НЕ СУЩЕСТВУЕТ: использовать MathF.PI / 180f.
- Сверять имена энумов (KeyboardKey, CameraProjection) с актуальной версией Raylib-cs.
- Полноэкранный режим реализовывать честно (флаг InitWindow / ToggleFullscreen).
- Каждый шаг должен компилироваться: выполнять dotnet build в окружении
  и показывать вывод консоли в сессии.
- Не оставлять пустых заглушек в критичных узлах: минимум рабочая реализация.
- Комментарии в коде — на русском. Не-русские комментарии запрещены.

## 6. Регламент работы сессий
- Начало сессии: git pull origin main + чтение этого файла.
- Агент работает в создаваемой платформой рабочей ветке.
- Агент НЕ удаляет и НЕ сливает ветки, НЕ публикует изменения сам:
  публикацию выполняет пользователь кнопкой Publish.
- Весь код писать файлами проекта в workspace, а не только текстом в чат.
- Одна сессия = один логический шаг из раздела 8; итерации внутри шага не ограничены.
- Конец сессии: обновить разделы 7 и 8 этого файла, включить в коммит.
- После публикации и слияния в main сессия закрывается; следующий шаг — новая сессия.

  Deg2Rad, имена энумов, заглушка полноэкранности) — требуют исправления. Перепроверить, если уже было исправлено.
